# Domain

A **Domain** represents a bounded context in the business or system architecture. Domains group related concerns, services, events, and actors. They are the fundamental unit of organization in the Flowti system.

Domain stubs live in the `docs/domains/` folder. Full domain documentation is generated by the plugin as `DomainDoc` files in `{docsRoot}/Domains/`.

## Frontmatter Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | `"Domain"` | yes | Document type discriminator |
| `domain` | string | yes | Domain name |

## Section Template

1. (Introduction paragraph — who this domain serves and why)
2. Key Concerns (bulleted list of domain responsibilities)

## Current Domains

| Domain | Primary Concern |
|--------|----------------|
| Business Operations | Operational workflows and daily business activities |
| Portfolio Management | Investment tracking, resource allocation, strategic alignment |
| Product Management | Product lifecycle, feature prioritization, roadmap |
| Project Management | Delivery planning, progress tracking, dependencies |
| Quality Management | Quality gates, reviews, compliance, continuous improvement |
| Supplier Management | Vendor relationships, contracts, service levels |

## Relationship to Plugin Domains

The `docs/domains/` folder contains business-level domain stubs. The plugin's internal domain model (`src/domain/`) uses bounded contexts for technical implementation:

| Plugin Domain | Business Domain |
|--------------|----------------|
| `session` | Project Management, Product Management |
| `dataExchange` | Business Operations |
| `docs` | Quality Management |
| `discovery` | Product Management |
| `subscription` | Business Operations |
