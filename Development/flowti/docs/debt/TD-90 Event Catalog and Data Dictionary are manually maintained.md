# TD-90: Event Catalog and Data Dictionary are manually maintained

## Problem

Two central reference documents are maintained by hand:

**Event Catalog.md** (598 lines)
- Documents 136 events across 11 domains
- States on line 23: "Objective: Make this document auto generated by Flowti on build"
- Source of truth is `catalog.ts` which uses `satisfies` for compile-time verification
- The catalog must be manually updated when events are added, renamed, or removed

**Data Dictionary.md** (541 lines)
- Documents 16+ document types with frontmatter schemas
- Also notes aspiration for build-time generation
- Must be manually updated when new document types are introduced

The PRD Audit (2026-02-15) already identified 9 phantom events — events referenced in PRDs that do not exist in the catalog. Manual maintenance is the root cause: when the catalog drifts from source, downstream documents inherit stale references.

## Impact

- Drift between documentation and source code is inevitable with manual maintenance
- Phantom events cause confusion — developers reference non-existent contracts
- New events added to source may not be reflected in documentation for weeks
- The self-documenting aspiration of the system is undermined by manual bottlenecks

## Suggested Remediation

1. Implement build-time generation of Event Catalog from `catalog.ts` type definitions
2. Implement build-time generation of Data Dictionary from frontmatter schema definitions
3. Until automation exists, add a "Last verified against source" date to both documents
4. Consider a CI check that compares generated output against committed docs to detect drift

## Resolution (Cycle 51)

Both documents are now auto-generated from TypeScript source during `npm run build`:

- **Event Catalog**: `scripts/generate-event-catalog.mjs` parses `src/infrastructure/events/catalog.ts` and generates `docs/reference/Event Catalog.md` (336 events, 36 categories, 23 domains)
- **Data Dictionary**: `scripts/generate-data-dictionary.mjs` parses `src/domain/docs/entityTypeRegistry.ts` and generates `docs/reference/Data Dictionary.md` (18 types, 131 fields)

Pure generator functions in `src/domain/docs/eventCatalogGenerator.ts` (17 tests) and `src/domain/docs/dataDictionaryGenerator.ts` (16 tests) ensure correctness. Phantom event detection identifies drift between source and documentation.

## Affected Files

- `docs/reference/Event Catalog.md` (auto-generated, replaces manual)
- `docs/reference/Data Dictionary.md` (auto-generated, replaces manual)
- `src/infrastructure/events/catalog.ts` (source of truth for events)
- `src/domain/docs/entityTypeRegistry.ts` (source of truth for entity types)
