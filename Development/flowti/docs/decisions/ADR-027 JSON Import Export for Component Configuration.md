# ADR-027: JSON Import/Export for Component Configuration

## Status

**Proposed** — not yet implemented.

## Context

Flowti manages several configuration types that users invest time creating:

| Config Type | Storage | Current Shareability |
|-------------|---------|---------------------|
| Saved Import Configs | TypedStorage (`DataExchangeState`) | None |
| Saved Export Configs | TypedStorage (`DataExchangeState`) | None |
| Saved Pipelines | TypedStorage (`DataExchangeState`) | None |
| Saved Session Templates | TypedStorage (`SessionState`) | None |
| Subscriptions | TypedStorage (`SubscriptionState`) | None |
| Event Definitions | TypedStorage (`EventDefinitionState`) | None |
| Plugin Settings | Obsidian `data.json` | Manual file copy |

Users cannot currently:
- **Share** a working import config with a teammate
- **Back up** their pipeline configurations independently
- **Transfer** configs between vaults (e.g., work → personal)
- **Version** a config by saving snapshots

### The Question: How Should Configs Be Shareable?

Three approaches considered:

1. **JSON clipboard copy/paste** — "Copy as JSON" button on each config, "Paste from JSON" to import. Lightweight, no file I/O.
2. **JSON file export/import** — "Export to file" writes a `.json` to a configurable folder, "Import from file" reads it back. File-based, vault-integrated.
3. **Markdown frontmatter** — Configs already generate documentation with frontmatter. Extend the doc format to be round-trippable (doc → config). Vault-native but complex.

## Decision

**Option 1 + Option 2: JSON clipboard and file export, with a shared serialization layer.**

All components must be able to export their configuration as JSON and import configuration from JSON. The serialization layer is shared:

```typescript
interface ConfigExport<T> {
    type: "import-config" | "export-config" | "pipeline" | "session-template" | "subscription" | "event-definition";
    version: 1;
    exportedAt: string;  // ISO timestamp
    data: T;
}
```

### Why Both Clipboard and File

- **Clipboard** is fastest for ad-hoc sharing (Slack, email, pair sessions)
- **File** is needed for vault-integrated workflows (version in git, include in templates folder, share via Obsidian Sync)
- The serialization format is identical — only the transport differs

### Why Not Frontmatter Round-Tripping

The documentation files generated by `ConfigDocService` are designed for human reading, not machine round-tripping. They use simplified tables and descriptions that lose information (column mapping `included` flags, conflict strategy details, UUID references). Making docs round-trippable would either bloat them or require a shadow section of raw JSON — worse UX than a dedicated export.

## Open Questions

1. **Should exported JSON include UUIDs?** If yes, importing could create duplicates. If no, a fresh UUID is generated on import and the config is treated as new.
2. **Bulk export?** Should "Export All Import Configs" be supported, or only individual configs?
3. **Validation on import?** Zod schema validation (ADR-017 pattern) could reject malformed JSON. How strict should validation be — reject unknown fields or strip them?
4. **UI placement?** Extra button on each config row, or a dedicated "Import/Export" section in the DX Hub?

## Consequences

### Positive

- **Portability** — configs work across vaults and installations
- **Backup** — users can snapshot their configuration independently of `data.json`
- **Sharing** — teams can standardize on shared import/export configs
- **Version 1 envelope** — forward-compatible via `version` field

### Negative

- **Surface area** — each config type needs serialize/deserialize + UI buttons
- **UUID handling** — deduplication or regeneration adds complexity
- **Validation** — imported JSON from external sources may be malformed or from a different version

### Neutral

- **No new service needed** — serialization can live as pure functions in `utils/` (ADR-023 pattern)
- **No schema changes** — the JSON format IS the TypedStorage format, just wrapped in an envelope
