The problem

Development teams live in fragmented tooling

Every project has its own scripts, its own conventions, its own quality bar. The result is invisible waste.

⚠ Before Flowti
  • Remembering which commands exist in which project
  • Script sprawl with overlapping, colliding names
  • Divergent build, test, and publish workflows
  • Stale documentation nobody reads or updates
  • No quality visibility across your project portfolio
  • AI agents blocked on unstructured interactive CLIs
✦ With Flowti
  • One binary manages every project via a unified interface
  • Named build & test modes — consistent across all projects
  • Gated publish pipeline: build → test → distribute
  • Self-documenting CLI Reference and Entity Reference
  • Health dashboard with A–F grades per project
  • Every action has a deterministic non-interactive equivalent

Capabilities

Everything a project needs, nothing it doesn't

Features activate only when you configure them. Start with a name — add thresholds, generators, and gates as you grow.

⚙
Build & Test Orchestration

Named build modes (fast, increment, full, watch, distribute) and test presets (unit, flows, e2e, increment) across all projects from one command.

📊
Health Dashboard

0–100 health scores with A–F grades, aggregating test, coverage, lint, git, security, and component metrics. Trend snapshots with delta indicators.

📄
Reports & Documentation

Six built-in generators: test, coverage, codebase, complexity, status, summary. Plus CLI Reference and Entity Reference. HTML export with timestamped archives.

🔗
Event Catalog & Contracts

Per-project event catalog with payload schema editor, versioning, and contract validation. TypeScript codegen and Mermaid flow visualization.

🏗
Project Scaffolding

Four project types (TypeScript, CLI, Obsidian plugin, library) and eight component kinds. Auto-scaffolds config from an existing package.json.

📋
Project Management

RAID log, CAPA tracking, deliverables, time-log, lifecycle state machine, and resource management — all as queryable Obsidian notes.

🤖
Agent-Native Design

Every interactive action has a non-interactive equivalent with deterministic exit codes and --format=json output. AI agents are first-class citizens.

🚀
Zero Runtime Dependencies

Ships as a self-contained Node.js binary using only built-ins. No npm install, no lock file conflicts, no version drift.

🗺
Sitemap-Driven UI

28 declarative pages in v2 PageObject format. Hot-reload support. The entire interactive menu is defined in a single auditable JSON file.

Ecosystem

Three layers, one coherent system

Each component is independently useful but designed to compose. The CLI orchestrates the others; they extend what the CLI manages.

CLI
Flowti CLI — The Orchestrator
Self-contained Node.js binary that manages build, test, publish, health, reports, events, scaffolding, and project management for any number of projects. 377 source files · 5,920 tests · 0 runtime deps.
Plugin
Flowti Plugin — The IBDE
An Obsidian plugin that implements the Integrated Business Development Environment concept. Events, flows, analytics, and test management as living knowledge-base notes. 21 bounded contexts · 7,697 tests · 406+ event types.
Agents
Agentonomous — The Sandbox
An Obsidian plugin for running, observing, and steering autonomous AI agents directly inside your vault. Currently in infrastructure build-out — the next frontier of the Flowti testbed. Vue 3 + DDD · Active development.
